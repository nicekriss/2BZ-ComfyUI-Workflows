# 설치기 검증 · 2026-09-22

대상은 기존 Windows ComfyUI 환경입니다. 새 ComfyUI 설치 기능은 사용자 요청에 따라 포함하지 않았습니다.

- 설치기 검사 7개 통과: 경로 이탈 거부, 로컬 주소 확인, 기존 모델 보존, 동명 모델 모호성 처리, 다운로드 Range 이어받기, SHA-256 오류 격리, 중단, Bridge 키 재사용, 임시 ComfyUI 구조에서 설치·재실행, 실행 중인 환경 변경 거부.
- 플러그인 JavaScript 검사 19개 통과. 연결 파일의 토큰·로컬 주소·허용된 모델 경로 검증 포함.
- 독립 EXE의 `--inspect`를 실제 `C:/mini/minimax/ComfyUI`에 실행: 공유 모델 경로를 읽어 8개 모델 모두 재사용 후보로 확인, 추가 다운로드 0 bytes, 실행 중인 ComfyUI 감지.
- 독립 EXE의 `--verify`를 실제 포트 8189에 실행: 선택한 ComfyUI 프로세스와 포트 연결, Bridge 토큰 인증, 템플릿 노드 존재 및 모델 선택값 검사 통과. GPU 작업은 제출하지 않음.
- 라인아트 원본 모델의 CPU FP16 변환 실행 성공. 이 변환의 출력 SHA-256을 다운로드 명세에 기록. 기존 검증 모델의 SHA-256도 재사용 허용 목록에 포함.
- Adobe UXP Developer Tools에서 `toobusy.photoshop.bridge` 버전 0.2.0 CCX 패키징 성공.
- Adobe UnifiedPluginInstallerAgent로 CCX 실제 설치 성공, `/list all`에서 Photoshop 27.10.0에 TooBusy AI 0.2.0 Enabled 확인. 테스트로 설치한 배포본은 제거했으며 기존 개발 플러그인과 SD-PPP는 유지.
- 배포 CCX의 config.json은 빈 토큰이며 개인 연결 키가 들어 있지 않음. 설치기는 대상 PC에 키를 생성하거나 기존 키를 재사용함.
- EXE의 한국어 설치 화면 실제 실행·레이아웃 확인.

기존 ComfyUI를 종료·재시작하거나 해당 환경에 노드·모델을 다시 설치하지는 않았습니다. 임시 환경 검사는 패키지 관리 명령을 모형으로 대체했으므로 의뢰인 환경의 pip 호환성까지 보장하지 않습니다. 모든 모델이 없는 의뢰인 PC에서 약 17.8 GiB를 새로 다운로드하고 최종 이미지를 생성하는 전체 과정은 현장 검수 대상입니다. 제공자의 로그인 요구, 오래된 ComfyUI와 노드의 버전 차이는 설치기가 구체적인 오류로 보고합니다.

Adobe 설치 확인과 Photoshop 연결 파일 선택은 사용자 조작 단계입니다. 자동 설치가 완료되었다고 오인시키지 않도록 파일 준비와 서버 연결 검사를 별도 상태로 표시합니다.

## 설치기 0.2.1 · Civitai 인증 개선

- 설치 창에 마스킹 API 키 입력란과 발급 페이지 버튼 추가. 401/403 시 입력 창에서 재인증하고 동일 다운로드를 자동 재시도합니다. 키는 이번 실행에서 다른 Civitai 모델에도 재사용합니다.
- 설치기 검사 총 13개 통과. 추가 6개는 인증 후 Range 이어받기, 나머지 모델의 키 재사용, 잘못된 키 재입력·취소 시 부분 파일 보존, CDN·다른 제공자에 키 미전송, 예외에서 서명 URL·키 비노출, HTTP 이동 거부, 키의 줄바꿈 입력 거부를 검사합니다.
- 0.2.1 독립 EXE 빌드 및 기존 ComfyUI의 `--verify` 연결 검사 통과. 플러그인 CCX는 검증된 0.2.0과 동일합니다.
- 인증 응답은 테스트 대역으로 검증했습니다. 실제 사용자 Civitai API 키로 제한 모델 전체를 받는 검수는 아직 하지 않았습니다. 0.2.1 EXE의 실제 화면에서 API 키 입력란·발급 버튼·하단 안내가 모두 보이는 것을 확인했습니다.

## 0.2.2 · 플러그인 업데이트와 실행 워크플로우 내보내기

- JavaScript 검사 29개, 설치기 검사 14개 통과. 다른 제품/초안 제외, 숫자 버전 비교, 누락된 CCX 안내, 출처·크기·SHA-256 검증, 실패/요청 제한 처리, 인증 키 미전송, 실행 그래프 값·동적 LoRA 연결 보존, 편집한 워크플로우 보존을 포함합니다.
- Adobe UDT로 정식 CCX 생성, 배포 ID와 빈 연결 키 및 패키지 소스 일치 검사 통과. Adobe UPIA로 0.2.0 설치 후 0.2.2 덮어 설치 성공. 기존 SD-PPP 유지 확인.
- 새 독립 EXE의 실제 ComfyUI 8189 연결·노드·모델 검사 통과. 개발 플러그인의 Photoshop 로드 및 결과 워크플로우 저장 버튼 표시 확인.
- 현재 설치된 ComfyUI 프런트엔드 소스에서 API JSON의 노드·위젯·링크 가져오기 지원 확인. 그래프 내보내기는 실행 데이터를 보존하며 입력 이미지 자체를 묶지는 않습니다. 이번 검사에서는 열린 ComfyUI의 미저장 작업을 교체하지 않았습니다.
- Photoshop 안에서 다운로드 버튼을 누른 뒤 Adobe 동의 창을 거쳐 완료하는 전체 UI 경로, 설정 유지의 의뢰인 PC 검수, 내보낸 그래프의 ComfyUI UI 재실행 검수는 남아 있습니다. 설치 패키지의 덮어 설치는 CLI로 검사했습니다. 인페인팅의 피부 비늘 증상이 해결되었다는 릴리스가 아닙니다.

## 0.2.3 · Illustrious 선택 영역 처리

- JavaScript 32개·설치기 14개 검사 통과. 영역 좌표/feather 픽셀/일반 생성 유지/LoRA와 제어 입력 연결 검사 포함.
- 기존 minimax 8189에서 추가 실행 13회 성공: 얼굴 1, VAE 왕복 1, 인페인팅 11. 실제 최종 makePrompt 경로로 Zeniji 결과 확인. WAI 눈 감기 성공률 문제와 Zeniji 회색 패치가 단일 비교 사례에서 개선됨. 원래 보고된 비늘 현상은 확정 재현하지 못함.
- 합성 결과 11개는 원래 마스크+50px 밖 픽셀 차이 0, 크기 1024×1024 유지. 임의 모델/입력의 품질 보장 아님.
- Adobe UDT 최종 CCX 패키징, 배포 ID/버전/빈 연결 키/패키지 소스 일치 확인. 개발 플러그인 Photoshop 재로드 성공. 이번 버전의 전체 Photoshop 싱크→생성→적용 UI 및 Adobe 업데이트 버튼부터 설치 완료까지의 UI 경로는 재검수하지 않음.
- 추가 모델/노드 설치 없음. KJNodes 고정 커밋의 ColorMatch 입력과 기존 요구 패키지 확인. 서버/열린 미저장 워크플로우 유지.
- [상세 대조와 결과](qa/illustrious-inpaint/REPORT.md)

## 0.2.4 · 생성 설정 및 프롬프트

- JavaScript 34개 검사 통과. 구버전 설정 이관, 체크 이벤트→저장→실행 그래프에서 라인아트 끔, 직접 다시 켠 설정의 저장·복원, 토글 재진입 검증 포함.
- 빈 파지티브/네거티브의 저장·복원·그래프 전달 확인. Photoshop 개발 플러그인 재로드 성공. 호스트에서 초기화/빈 입력/체크박스의 전체 클릭 경로는 이번 검증에서 완료하지 않음.
- 생성 설정 초기화 범위는 생성 옵션/프롬프트/모델 배합이며 연결·프리셋·이미지 저장소를 지우지 않음. 생성 추적 중 초기화 버튼 비활성화.
- GPU 샘플링 구조는0.2.3과 동일하며 이번 릴리스에서는 추가 샘플링을 하지 않음. 피부 비늘 증상 확정 재현/완전 해결 판정 아님.
